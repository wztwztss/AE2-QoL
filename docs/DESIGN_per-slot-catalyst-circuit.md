> **我们通配样板里的 GT 编程电路换成 PH:编程器电路**、**不消耗物品也转成编程器版本**（见 CHANGELOG (46)）。
> 本文**仅作存档**，不再实施。

> **状态：暂存（shelved）**：本文只记录需求与设计，**不动代码**。
> 提出：2026-09-27（用户）；口径修订：2026-09-27 晚（用户：「在不删除内置电路的基础上再加上独立的电路槽和不消耗物品槽，按鼠标中键打开」）。

## 一、为什么要做（动机与证据）

### 1.1 冲突机制（已定位）
现有实现把"电路"放在**样板**里（样板 NBT 子树 `ae2qolSmartWildcard/Circuit`），索引期由
`SmartWildcardCircuit.apply(...)` 把该号写进**机器唯一的虚拟电路槽**。
⇒ 同一舱室放两张通配样板时，**后索引的那张覆盖前一张的电路值**，两张样板实际上共用了一个电路。
用户实测（2026-09-27）：MK.III 上"第一张样板是 1 号电路、第二张是 2 号电路，后放进去的会覆盖前面的"。

### 1.2 结论
"电路"与"催化剂"本质是**机器某个样板格此刻的工艺参数**，不是"这张样板覆盖哪些配方"的一部分。
把它们做成**按格独立**，冲突自然消失；而现有的"样板自带电路"**保留**（作为兜底与向后兼容），
优先级遵循"**每格设置 > 样板自带 > 整机设置**"（详见 §2.2）。

### 1.3 已有的基础（不用从零做）
本模组**已经**有一个中键手势：`mixin/mui/MixinItemSlotWildcardGesture` 拦 `ItemSlot.onMousePressed`，
对智能通配样板弹出轻量电路选择屏，并由 `SmartWildcardSlotCircuitPacket` 把电路号写回**样板 NBT**。
本设计把它**扩展**为：中键打开**该格的设置面板**（电路 + 催化剂），数据**写到机器**（按格保存），
样板 NBT 那条写回路径保留原样不动。

## 二、目标设计

### 2.1 一句话
> **保留样板自带的电路/不消耗物品；另外给每个样板格加一个"格设置"：该格独立电路 + 该格独立催化剂，
> 用鼠标中键在样板格上打开。**

### 2.2 取值优先级（取用时）
1. **该格独立电路**（新增，机器侧按格保存）→ 命中就用它烧成电路物品随该格输入推进总线；
2. 该格没有设置时 → 沿用**样板自带电路**（现有行为，`state.circuit`）；
3. 样板也没带 → **整机设置**（现有机器自己的电路控件，完全不动）。
催化剂同理：**该格催化剂**优先；否则用样板自带的 `NonConsumed`；都没有就不注入。

### 2.3 涉及的宿主（五处，全部都要有）
| 机器 | MTE / 类 | 备注 |
|---|---|---|
| GT 样板输入总成 | 2714 / 2715 `MTEHatchCraftingInputME` | |
| GTNL 超级样板输入总成 | 21504 / 21505 `SuperCraftingInputHatchME` | 144 格 |
| PH 编程样板输入总成 | 22069 `PatternDualInputHatch` | 原版 36 格 |
| PH MK.II | 22179 | 36 格 |
| 本模组 MK.III | 32108（继承 PH 基类） | 144 格 |
> AE2 ME 接口/样板供应器那条链没有"每格"概念，**不覆盖**，继续沿用样板自带 + 玩家手动。

### 2.4 数据模型（机器侧，按格对齐）
```text
机器 NBT 新键：ae2qolSlotMeta（NBTTagList，按样板槽下标对齐）
  每项：{ Slot:int, Circuit:int(-1=未设置/继承), Catalyst:{ItemStack NBT} }
```
- `Circuit`：`-1` = 未设置（走样板自带 → 整机）；`1..24` = 该格指定；
- `Catalyst`：单个 ItemStack（可空）；
- **按下标对齐**：GTNL 会自动整理、玩家会移动样板 ⇒ 整理/变更后按下标重排，无法对齐时**打 WARN**（不静默错位）；
- 跟随机器 `markDirty()` 持久化；区块重载后保持。

### 2.5 生效方式（关键：怎么"按格"起作用）
取用发生在**该格 push 的那一刻**（GT/GTNL/PH 三族的槽位 `insertItemsAndFluids` 路径）：
1. **电路**：把该格的电路号**烧成一个电路物品**（`gt.integrated_circuit`，damage = 该号），
   随该格输入一起推进输入总线 —— 这正是 GTNH 原生"样板带电路"的机制，机器按这一格的电路匹配配方，
   **不再需要动机器唯一的虚拟电路槽**，因此两张样板互不覆盖；
2. **催化剂**：把该格催化剂物品**一并推进输入总线**，但它**不写进样板的 in 列表** ⇒
   AE 不会去凑它、也不会消耗它（GT 的 notConsumed 配方语义）；催化剂实物保存在该格自己的槽位里，可反复使用；
3. 该格未设置时，行为与现在**完全一致**（回落到样板自带/整机）。

### 2.6 UI（中键打开"该格设置"面板 · 一屏搞定 · 已按用户拍板定稿）
现有中键手势（`MixinItemSlotWildcardGesture`）已经会对样板格弹窗，本次把它扩成"**格设置面板**"。
弹窗是**我们自己的轻量 GuiScreen**（`GuiSlotCircuitPicker` 升级版），因此**宿主机器的 GUI 布局完全不动**。

        │  [ 通配样板 ]   │  ← 鼠标中键点这里
        └────────────────┘
                 │ 中键
                 ▼
 ┌───────────────── 样板格 N 的设置 ─────────────────┐   ← 浅底深字，不用 § 颜色码
 │ 电路                                                    │
 │  [ 继承 ]  [ 1] [ 2] [ 3] [ 4] [ 5] [ 6] [ 7] [ 8]      │   ← 12 列 × 2 行按钮
 │            [ 9] [10] [11] [12] ………… [23] [24]          │      "继承"= 该格不设，走样板自带→整机

（尺寸待实施时按轻量屏实际像素排：目标约 240×210，两行电路按钮 + 3×3 催化格 + 底部两键。）

交互约定：
- **只影响被点的那一格**；标题写明槽位号（如"样板格 3 的设置"）；
- 写入走**一次轻量 C2S 包**（`{x,y,z, slot, circuit|-1, catalyst[9]}`），服务端校验
  BUILD 权限与距离后写机器 NBT + `markDirty()`；失败必须留日志（本仓"不许静默降级"原则）；
- 中键手势适用范围沿用现有实现（GT / GTNL / PH 家族的 MUI2 `ItemSlot`；AE2 原生 `Slot` 不触发）；
- 催化格内容**只在弹窗里展示**，机器主界面不铺开（144 格 × 9 格装不下）。

## 四、已确认口径（2026-09-27 晚，用户逐条拍板）

| 问题 | 用户决定 |
|---|---|
| 面板形式 | **一屏搞定**：电路 1~24 按钮 + 催化剂格（不做页签） |
| "继承"语义 | **该格留空 → 样板自带 → 整机**（三级，兼容现有行为） |
| 催化剂机制 | **用户自定义**：「每次我单独放，合成的时候被推进总线，合成完返回」＝ 催化剂实物由玩家放进该格的催化位，push 时随该格输入推进输入总线，**配方按 notConsumed 语义不消耗**，**合成结束要返回**（回到该格催化位，而不是回 AE） |
| 每格催化位数 | **9 个**（3×3） |
| 落地顺序 | **五处机器一起做**（2714 / 21504 / 22069 / MK.II 22179 / MK.III 32108） |
| 旧机制（`SmartWildcardCircuit` 索引期写机器虚拟电路槽） | 待用户答复（见 §4.1 白话解释）——**推荐**：该格有设置就不写机器槽（消除互相覆盖）；该格没设置就保持现状（今天单张样板的行为不变） |

### 4.1 第 6 问已由用户第 4 点答复（**最终口径**）
> 用户（2026-09-27 晚）：「**样板内置的电路放进去后就自动识别到这个每格单独的电路槽，而不是去修改全局的电路槽。
> 然后这个单独的电路槽玩家也可以手动修改。**」

⇒ 这就是答案，比我原来的两个选项都干净：**把"抄到全局电路槽"改成"抄到本格电路槽"**。
- **插入/索引样板时**：若该格**尚无**显式电路值，就把**样板自带电路**自动填入**该格**的电路槽（= 自动识别）；
- **绝不**再改动机器那个全局电路设置 ⇒ 两张样板永不互相覆盖，全局旋钮**交还给玩家**手动；
- 玩家随时可以在"该格设置"弹窗里**手改覆盖**（优先级最高）。

**最终三级取值（自上而下）**：
1. **玩家手改的每格值**（最高，弹窗里设的）
2. **样板自带电路自动填入的每格值**（插入时自动识别，仍可被 1 覆盖）
3. **整机设置**（我们完全不碰，玩家自己用）

**行为变更提醒**：`SmartWildcardCircuit`（原来索引期写**全局**槽）改为写**本格**；因此这件事必须与"每格电路槽"**同一版上线**
（提前单独改会让"样板自带电路"失去生效途径）。

### 4.1b 旧机制降级（第 6 问的历史表述，保留备查）
机器里有一个**整机电路设置**；今天我们的做法是每次重新索引样板时把**样板自带的电路号抄写到那个整机设置**里
⇒ 两张样板互相覆盖（"后放进去的会覆盖前面的"）。现在按 §4.1 的最终口径：**不再抄到整机，改抄到本格**。

### 4.2 技术风险（实施前必须先验证，记录备查）
> **2026-09-27 首次只读核实结果（javap）**：
> 1. **GT `PatternSlot.refund(AENetworkProxy, BaseActionSource, boolean)` 是把 `itemInventory` 里的东西
>    `Platform.poweredInsert(...)` 回 AE 网络的**（不是退回"本格"）⇒ 想让催化剂"合成完回到那 9 格"，
>    **不能依赖 GT 的 refund**，必须由我们自己做"回收"（把机器总线/槽位里的催化剂取回本格 9 格）；
> 2. **GT `insertItemsAndFluids(MEInventoryCrafting)`** 逐槽读 `getAEStackInSlot` 后分流到 `insertItem/insertFluid`
>    ⇒ GT 侧注入点就是我们自己的 `SmartWildcardPatternSlot`（可覆写，最干净）；
> 3. **PH 家族**：`PatternDualInputHatch` 只有若干内部类（`$Inst/$DA/$1..$4/...`），
>    样板推入走的是 GT 的 `IDualInputHatchWithPattern` / `IDualInputInventoryWithPattern` 体系 ⇒
>    PH/MK.III 的注入点与回收点还需要继续挖掘（下一步只读任务）。

### 4.4 三族推入/回收点调研结论（只读 javap，2026-09-27）
| 宿主 | 推入方法 | 注入方式 | 未消耗物容器 | 回收 |
|---|---|---|---|---|
| GT 2714/2715 | `PatternSlot.insertItemsAndFluids(MEInventoryCrafting)` | **覆写我们自己的 `SmartWildcardPatternSlot`** | 槽位 `List<ItemStack> itemInventory`（protected final） | `refund(...)` **回 AE**，不可用 ⇒ 自建 |
| GTNL 21504/21505 | `PatternSlot.insertItemsAndFluids(InventoryCrafting)`（签名与 GT 不同！） | **覆写 `SmartWildcardGtnlPatternSlot`** | 同上（public final） | 同上（`refund` 也回 AE） |
| PH 22069 / MK.II / MK.III | `PatternDualInputHatch.pushPattern(details, InventoryCrafting)`（`BufferedDualInputHatch.pushPatternCM` 转调它） | **基类一处 mixin 即覆盖三台**（MK.III = `MTEPatternCraftingBufferMKIII extends PatternDualInputHatch`，不覆写这些方法） | `BufferedDualInputHatch$DualInvBuffer.mStoredItemInternalSingle`（protected，需 accessor） | 同上（`refundAll` 回 AE） |

**自建回收的三个真实风险（用户批准"一次做完"时还不知道，务必先看）**：
① "移出 → 推入 → 回收"三步之间若中断（区块卸载/机器被拆/合成取消），催化剂**可能丢失或复制** ⇒ 必须加日志 + 可重入保护；
② **PH 的缓冲参与 `recipeLocked/inTree/lock` 配方树判定**，额外塞进去的催化剂可能干扰它的分类 ⇒ PH 侧风险最高；
③ 催化剂**只有在配方确实声明 notConsumed 时**才该注入，否则会被当消耗品吃掉。

### 4.5 已识别的构建期坑（本轮实际踩到）
- **PH 在编译期的包名是 `reobf.proghatches...`**（不是 `proghatches...`）：`dependencies.gradle` 里是
  `compileOnly(project.files("libs/programmablehatches-0.2.0p24.jar"))`，jar 内类以 `reobf.` 前缀提供。
  写 `import proghatches....` 会直接编译失败（"程序包不存在" + "Mixin has no targets"）⇒ 新写 PH 相关代码必须用 `reobf.proghatches...`。

### 4.7 分期建议（历史建议，用户已选择"一次做完"；4.4 的风险请一并权衡）
- **A 期（原建议）**：
  ① 机器侧按格数据 `ae2qolSlotMeta`（电路 + 9 催化位，稀疏保存）；

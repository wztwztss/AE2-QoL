# 设计稿（暂存·本轮不实施）：样板只管规则，电路与催化剂下沉到"每格独立设置"

> **状态：暂存（shelved）。** 本文只记录需求与设计，**不改任何代码**。
> 提出时间：2026-09-27。提出人：用户。整理：DSH（DeepSeek-V4.1-Flash）。
> 启动条件：**等"通配样板在 GT 样板总成里不合成"这条主 bug 彻底修完并验收通过之后**再开工；
> 按用户 UI 铁则，实施前需先把本文的线框稿敲定。

## 一、为什么要改（动机与证据）

### 1.1 现状（要移除的东西）
当前智能通配样板把两类"机器侧语义"**塞进了样板自己**：

| 现在放在样板里的东西 | 数据位置 | 谁在用 |
|---|---|---|
| 内置电路号（1~24 / 继承） | 样板 NBT 子树 `ae2qolSmartWildcard/Circuit` | 索引期由 `SmartWildcardCircuit.apply(...)` **写进机器的虚拟电路槽**（GT / GTNL / PH 三处调用） |
| 不消耗物品（催化剂）列表 | 样板 NBT 子树 `ae2qolSmartWildcard/NonConsumed` | 随样板走；界面在 Wild 窗口「不消耗物品」页与 MUI2 编辑器对应页维护 |

### 1.2 用户实测（2026-09-27，关键新证据）
> 「把通配符样板放到 **AE2 原版的样板供应器**，然后贴到输入总线上，发现**可以正常发配物品材料**，
> **电路手动设置的情况下就完全正常**。」

这条对照说明三件事：
1. **样板的展开与 AE 注册这条链本身是通的**（放到 AE2 原生供应器里就能被 AE 认、能推送材料）；
2. **机器侧并不排斥我们的具体样板**（材料真的被送进输入总线并参与了配方）；
3. **"电路由谁设置"是决定成败的变量**：手动设置 ⇒ 正常；由样板/自动机制插手 ⇒ 不正常。

### 1.3 由此得出的设计判断
"电路"与"催化剂"本质是**机器某个样板格此刻的工艺参数**，不是"这张样板覆盖哪些配方"的一部分。
把它们放进样板会带来三类问题（都在本仓实际发生过）：
- **双电路**：样板里带电路物品（模板输入里的 `gt.integrated_circuit`）**同时** M3 又把号写进机器的虚拟电路槽；
- **越权覆盖**：索引期自动写机器的虚拟电路槽，可能**覆盖玩家手动设置的电路**（用户实测手动设置才正常）；
- **数据跟着样板走、无法按格微调**：同一张样板放进不同机器/不同格，本应可以有不同的电路与催化剂。

⇒ 结论：**样板只描述"配方覆盖范围"（通配规则/黑白名单/排除），电路与催化剂改为机器侧、按样板格独立保存与设置。**

## 二、目标设计（一句话）
> **每个样板总成的每一个样板格，各自带一个「电路设置」与一个「催化剂槽」；样板里不再保存、也不再联动这两样。**

### 2.1 涉及的五处宿主（全部都要有）
| 机器 | MTE / 类 | 现有虚拟电路支持 | 备注 |
|---|---|---|---|
| GT 样板输入总成 | 2714 / 2715 `MTEHatchCraftingInputME` | 有（M3 现在就在写） | 用户实测：能下单但不合成，手动电路才正常 |
| GTNL 超级样板输入总成 | 21504 / 21505 `SuperCraftingInputHatchME` | 有 | 144 格 |
| PH 编程样板输入总成 | 22069 `PatternDualInputHatch` | 有 | 原版 36 格 |
| PH MK.II | 22179 | 有 | 36 格 |
| 本模组 MK.III | 32108（继承 PH 基类） | 有 | 144 格 |

> 另有 AE2 ME 接口/样板供应器一条链：**没有"每格"这个概念**（它的样板是接口自己的槽位），
> 那条链本轮设计**不覆盖**，仍沿用"样板自带电路"或"玩家手动设置"的既有行为（见 §6 待定项）。

### 2.2 数据模型
```text
机器 NBT 新键：ae2qolSlotMeta（NBTTagList，按样板槽下标对齐）
  每项：{ Slot:int, Circuit:int(-1=继承), Catalyst:{ItemStack NBT} }
```
- `Circuit`：`-1` = 继承（机器整机电路），`1..24` = 该格指定；
- `Catalyst`：单个 ItemStack（可空），语义＝"该格合成时不消耗/作为催化剂"；
- **按槽位下标对齐**：GTNL 有"自动整理"、玩家会移动样板 ⇒ 需要在 `onPatternChange` / 整理动作后
  按物品身份（或至少按下标）重排；无法对齐时记 WARN，不静默错位。
- 优先级（沿用既有约定并简化）：**每格设置 > 整机设置**；样板里**不再参与**电路优先级。

### 2.3 UI（每个样板格旁两个控件）
```text
┌ 样板总成 GUI（示意；实际尺寸按各自现有窗口定） ───────────────────────────┐
│  ┌──────────────┐  ┌──────┐  ┌──────┐                                    │
│  │  样板格 (N)   │  │ 电路 │  │催化剂│   ← 样板格 = 现有槽位（不改其行为）  │
│  │  [ 样板物品 ] │  │ [ 1 ]│  │ [ ▢ ]│      电路：点击弹出 1~24 / 清除（继承）│
│  └──────────────┘  └──────┘  └──────┘      催化剂：可放/可拖入/可清空       │
│  ┌──────────────┐  ┌──────┐  ┌──────┐                                    │
│  │  样板格 (N+1) │  │ [继承]│  │ [ ▢ ]│                                    │
│  └──────────────┘  └──────┘  └──────┘                                    │
│  … 其余格子同样布局；整机电路设置控件保持原位                              │
└───────────────────────────────────────────────────────────────────────────┘
```
交互约定（沿用本仓既有手法，避免踩过的坑）：
- **电路**：小按钮显示当前值（`继承` / `1`..`24`），点击打开既有 `GuiSlotCircuitPicker`（1~24 / 清除）；
- **催化剂**：一个真实 `ItemSlot`（MUI2 `ItemSlot` / GTNH-MUI 对应控件），**支持 NEI 拖入**；
- 双端构建一致（MUI2 面板双端各构建一次 ⇒ 权限校验写在服务端 setter，不在构建期）；
- 只在玩家**有 BUILD 权限且距离足够**时允许写（沿用库存终端那条鉴权链）。

### 2.4 同步与持久化
- 单格改动 = **一次轻量 C2S 包**（`{x,y,z, slot, circuit|-1, catalystStack|null}`），服务端校验后写机器 NBT + `markDirty()`；
- GUI 显示用 `IntSyncValue` / `ItemStack` 同步（或打开时一次性下发快照）；
- 失败必须留日志（本仓原则：不许静默）。

### 2.5 移除的范围（"删除电路和不消耗物品的样板设置"具体指什么）
| 对象 | 处理 |
|---|---|
| Wild 窗口「电路」页签 | **移除**（连同 3.33.0 起就存在的底部电路带已撤） |
| Wild 窗口「不消耗物品」页签 | **移除** |
| MUI2 四页签编辑器里的「电路」页与「不消耗物品」内容 | **移除**（编辑器其余功能保留） |
| 样板 NBT 里的 `Circuit` / `NonConsumed` 键 | **不再写入、不再读取**；旧数据**保留不动**（不删玩家数据），仅不再参与行为 |
| `SmartWildcardCircuit`（M3 自动写机器虚拟电路槽） | **停用**（这是"覆盖玩家手动电路"的源头） |
| 语言键 `gui.wildcardpattern.circuit_*` / `nonconsumed_*` | 随页面一起移除（或保留待用，实施时定） |

> ⚠️ 兼容：旧样板里已有的 `Circuit/NonConsumed` 不再生效，属**行为变更**，实施时要在聊天栏/指南明确告知。

### 2.6 与本 bug 的关系（**2026-09-27 更新：电路已被实测排除**）
> ⚠️ **最新结论（用户实测，2026-09-27）**：**停用 M3 自动写虚拟电路 + 手动设置电路，仍然不能合成。**
> ⇒ **电路不是"能下单但不合成"的原因**（此前基于"AE2 原生样板供应器 + 手动电路正常"的推断被实测否掉）。
> ⇒ 因此本设计稿的性质改为：**纯 UI/架构改进（把工艺参数放回机器侧、按格独立）**，
> **不是修 bug 的必需项**。实施优先级由用户决定，仍按"先出线框稿再动代码"的规矩来。

用户实测：**手动设置电路时一切正常**。这说明当前"样板自带电路 + M3 自动写虚拟槽"很可能是
"GT 样板仓能下单但不合成"的直接原因之一（自动写入覆盖/扰动了玩家设置）。
因此：
- **短期**（修 bug 阶段）：先按证据把 M3 的自动写入行为查清并处置（停用/降级为"仅当机器为继承时才写"）；
- **长期**（本文）：按 §2 的设计把电路与催化剂彻底下沉到"每格独立"。

## 三、验收标准（实施时用）
1. 五处机器的每个样板格都能独立设置电路与催化剂，且**重启/区块重载后保持**；
2. 样板里不再有电路/不消耗物品设置（Wild 窗口与 MUI2 编辑器相应页移除）；
3. **玩家手动设置的整机电路不再被任何自动逻辑覆盖**；
4. 同一张样板放进不同机器/不同格，电路互不影响；
5. NEI 拖入催化剂可用；删除/替换样板后，该格设置按 §2.2 的对齐规则处理并有日志；
6. 中英语言键与指南页同步；README/CHANGELOG/MOD_MAP 记录本次行为变更（移除样板侧电路/催化剂）。

## 四、待用户拍板的问题（实施前必须回答）
1. **催化剂槽的语义**：是"该格不消耗的物品"（铸模/模头/透镜），还是也包括"必须消耗的额外材料"？
2. **一格多个催化剂**？还是一个槽一位（多个时改成列表＋分页，与本仓既有列表范式一致）？
3. **旧样板里的 `Circuit/NonConsumed`**：直接忽略（推荐）？还是在首次放入机器时**迁移**到该格设置？
4. **整机电路控件**是否保留？（倾向保留：催化剂/电路都做成"每格 > 整机"两级）
5. 五处机器的 GUI 改动量很大（GT 走 MUI2、PH 走自绘/自有 GUI），是否**先做 GT 2714 + 我们的 MK.III** 两处，
   验完再铺开？

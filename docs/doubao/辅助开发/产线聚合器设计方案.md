> **文档用途**：产线聚合器的完整设计思路，随需求演化持续迭代。**本文件是"唯一的权威方案来源"，代码改动前必须先更新此文档并获确认。**
> **状态**：设计已确认（v1.0），等待用户指令"开始动手写"后方可实施。**禁止在用户明确允许前改动任何代码。**
> **目标版本**：v3.20.0（仿 GTL 一步产线系统）

## 一、需求背景与核心理念

GTNH 中许多复杂工艺（如轻燃油、铂处理、PBI）需要几十步中间流程。**产线聚合器**将完整多步骤产线合并为**单一方块**处理：

- 玩家放入**全部输入**（所有原材料 + 中间需要的原料，含循环物品）
- 机器自动匹配配方，一次性产出**全部输出**（最终产物 + 全部副产物 + 中间产物）
- **子线合并**：铂处理/稀土处理/硅岩处理等有多条子线的产线，合并成一支配方
- **循环物品作催化剂**：某物品输入量=输出量时，标记为催化剂，**不消耗但必须存在**才能运行（输入输出都保留）
- **重复配方跳过**：与已有配方本质相同（如氧产线与氢产线同为水电解，只是输出侧重不同）的产线不单独配平

参考：GTL 一步产线（`E:\wzt\MC\modcreater\reference_src\一步产线参考代码（GTL适配）`，KubeJS 脚本形式）。

## 三、整体架构

```
                    ┌─────────────────────────────┐
                    │  5×5×5 多方块结构             │
                    │  - MTEProductionLineAggregator│ (主方块 32120)
                    │  - MTEHatchProductionLineController│ (控制器仓 32121)
                    │  - 机器外壳(分等级)            │
                    │  - 能量仓(决定电压/功率)        │
                    │  - 输入仓/输入总线              │
                    │  - 输出仓/ME 输出总线           │
                    └────────────┬────────────────┘
                                 │
                    ┌────────────▼────────────────┐
                    │  ProductionLineRecipeMap      │
                    │  (RecipeMap, NEI 自动显示)     │
                    └────────────┬────────────────┘
                                 │
                    ┌────────────▼────────────────┐
                    │  ProductionLineRecipe         │
                    │  - id / name / category        │
                    │  - minVoltageTier              │
                    │  - inputs (items+fluids)       │
                    │  - outputs (items+fluids)      │
                    │  - euPerTick / duration        │
                    │  - parallel / requiredMachines │
                    └────────────┬────────────────┘
                                 │
                    ┌────────────▼────────────────┐
                    │  ProductionLineRecipeLoader   │
                    │  (解析 config/ae2_qof/        │
                    │   production_lines/*.json)    │
                    └─────────────────────────────┘
```

### 核心数据流
1. **加载**：`ProductionLineRecipeLoader` 启动时扫描配方目录，解析 JSON
2. **注册**：`registerRecipe()` 将每条配方转成 GT Recipe 注册进 RecipeMap
3. **匹配**：多方块结构放入输入 → `checkInputs()` 在 RecipeMap 中找匹配配方
4. **校验**：`checkMachine()` 校验外壳等级 ≥ 配方 minVoltageTier；能量仓电压 ≥ euPerTick
5. **执行**：`processRecipe()` 消耗输入 → 产出全部输出 → 超频（按能量仓电压 overclock）

## 四、JSON 配方 Schema（v1.0 已确认）

```jsonc
{
  "type": "production_line",
  "id": "hydrogen",
  "name": "氢产线",
  "category": "lv_gas",
  "description": "水电解产氢",
  "minVoltageTier": 1,          // LV=1 最低外壳等级要求
  "requiredMachines": [          // 激活消耗的机器物品（可选）
    { "item": "gregtech:gt.metaitem.01", "meta": 1000, "count": 1 }
  ],
  "inputs": {
    "items": [
      // 净输入物品（可空数组）
    ],
    "fluids": [
      { "fluid": "water", "amount": 1000 }
    ]
  },
  "outputs": {
    "items": [
      // 最终产物+全部副产物（物品）
    ],
    "fluids": [
      { "fluid": "hydrogen", "amount": 2000 },
      { "fluid": "oxygen", "amount": 1000 }
    ]
  },
  "euPerTick": 30,              // 基础耗电 EU/t
  "duration": 100,              // 基础耗时 tick
  "parallel": 64                // 最大并行（受 maxParallel 配置上限约束）
}
```

**要点**：
- 无 `steps` 字段（不记录中间步骤）
- `inputs` 是**全部输入**（原材料 + 中间料 + 循环物品/催化剂），不再是净输入
- `outputs` 含最终产物 + 全部副产物 + 中间产物
- **催化剂识别**：某物品在 `inputs` 和 `outputs` 中同时存在且 amount 相同 → 自动识别为催化剂，不消耗但必须存在
- `minVoltageTier` 用于外壳等级校验
- **子线合并**：多子线产线（铂/稀土/硅岩）合并为单条 JSON，输入输出汇总所有子线

## 六、关键设计细节

### 6.1 外壳等级限制（问题 6C 确认）
- 外壳方块有多个等级（如 LV/MV/HV/EV/IV/LuV 机器外壳）
- `checkMachine()` 扫描结构，读取**最低外壳等级**作为机器等级
- 配方 `minVoltageTier` > 外壳等级 → 报"外壳等级不足"不可运行
- 能量仓等级决定实际可用电压 → 决定是否超频、超频多少档

### 6.2 激活机制（每结构独立）
- 激活状态存**控制器仓 NBT**（`activatedRecipes` 列表，已有实现基础）
- 放机器物品 → 点击激活 → 消耗物品 → 写入 NBT → 永久激活该配方
- 每台多方块独立，互不影响
- 原 `MachineConsumptionManager`（全局 WorldSavedData）与"每结构独立"冲突，方案为**废弃**（或仅保留为兜底）

### 6.3 输出槽"无限大"
- 用户：多方块机器接 ME 输出总线，多少类型都放得下
- 实际约束：RecipeMapBuilder.maxIO 的 int 参数有上限
- **待确认**：GTNH 2.9.0 RecipeMapBuilder 允许的最大槽数；若 maxIO 不够，需调研替代方案（如超大 RecipeMap 或自定义输出存储）

### 6.4 配方匹配
- 纯 GT 风格：放入输入 → 自动在 RecipeMap 查找匹配配方（`findRecipe`）
- 不需要点击选择
- NEI 自动显示（RecipeMap 注册机制）

### 6.5 电压等级表（GTNH）
| 等级 | 电压 |
|---|---|
| LV | 32 EU/t |
| MV | 128 EU/t |
| HV | 512 EU/t |
| EV | 2048 EU/t |
| IV | 8192 EU/t |
| LuV | 32768 EU/t |
| ZPM | 131072 EU/t |
| UV+ | 更高 |

### 6.6 子线合并与催化剂处理规则（v1.1 新增）

**子线合并**：
- 铂处理（7子线：铂/钯/铂渣/铑/钌/锇/铱）→ 合并为 1 条"铂处理"配方
- 稀土处理（8子线：独居石/氟碳镧铈/钐精粉主线 + 5分支）→ 合并为 1 条"稀土处理"配方
- 硅岩处理（3子线：硅岩/富集硅岩/超能硅岩）→ 合并为 1 条"硅岩处理"配方
- 合并方式：输入 = 所有子线的原材料 + 中间需要的原料；输出 = 所有子线的产物 + 中间产物
- 合并后配方的 `minVoltageTier` = 所有子线中的最高等级
- 合并后 `euPerTick` = 所有子线中的最大值（或总和，待实施时确认）
- 合并后 `duration` 取所有子线中的最大值（或加权平均，待实施时确认）

**催化剂/循环物品处理**：
- 判定规则：某物品（物品或流体）在 `inputs` 和 `outputs` 中同时存在，且 **amount 完全相同** → 自动识别为催化剂
- 催化剂行为：
  - **不消耗**：运行后输入槽中的催化剂数量不变
  - **必须存在**：输入槽中必须有至少 amount 数量的催化剂才能启动配方
  - **输入输出都保留**：JSON 中 inputs 和 outputs 都列出该物品（amount 相同）
- 典型催化剂：盐酸（铂处理中循环）、氯气（钛处理中循环）、空单元（电解配方中，已决定跳过）
- **传统独立催化剂**（如电路配置、GT 配方中的 circuit）：不进 JSON，完全跳过

**重复配方跳过**：
- 氧产线 = 氢产线的反向输出（同为水电解，只是 circuit 不同）→ 跳过，不配平
- 蒸馏水变体 = 普通水变体的数值完全相同 → 不单独配平（或作为同一配方的可选输入，待实施时确认）
- 判断标准：核心化学反应相同，只是输入形式或输出侧重不同 → 跳过

### 6.7 requiredMachines（激活解锁用机器）规则（v1.2 新增，v1.3 修正）

**用途**：每条配方的 `requiredMachines` 字段列出该产线**每一步**需要用到的多方块机器主机物品。激活配方时，玩家需将这些机器物品放入控制器仓，点击激活后消耗这些物品，永久解锁该配方。

**选取规则**：
1. **每一步一台机器**：产线有几个步骤，就列几台机器（一步一台，不是只列关键机器）
   - 例：轻燃油产线有蒸馏+脱硫两步 → 蒸馏塔×1 + 大化学反应机×1
   - 例：太阳能级硅产线有氯化+还原两步 → 大化学反应机×2（两步都用大化学反应机）
   - 例：聚乙烯产线有脱水+聚合两步 → 大化学反应机×2
2. **优先用多方块机器的主机**（控制器方块），不要用单方块机器
   - 若某步骤原版用单方块机器（如化学反应机），则用对应的多方块版本（如大化学反应机 UniversalChemical）替代
   - 大化学反应机（UniversalChemical）可执行大部分单方块化学反应机（chemicalReactorRecipes）的配方
3. **只列产线核心步骤用到的机器**，不列辅助机器（如能量仓、输入总线、输出总线等通用部件）
4. 同一种机器在不同步骤使用时，**分别列出**（一步一台，数量累加）
5. 机器物品用 `item`（注册名）+ `meta`（伤害值）+ `count`（数量）标识，实施时从 GTNH ItemList 枚举确认准确值

**典型产线所需多方块机器参考（每步一台）**：
| 产线 | 步骤1机器 | 步骤2机器 | 步骤3机器 | 合计 |
|---|---|---|---|---|
| 氢产线 | 工业电解机×1 | — | — | 1台 |
| 轻燃油产线 | 蒸馏塔×1 | 大化学反应机×1 | — | 2台 |
| 太阳能级硅产线 | 大化学反应机×1 | 大化学反应机×1 | — | 2台 |
| 聚乙烯产线 | 大化学反应机×1 | 大化学反应机×1 | — | 2台 |
| 高十六烷值柴油 | 蒸馏塔×1 | 大化学反应机×1 | 大化学反应机×1 | 3台 |
| 钛处理产线 | 大化学反应机×1 | 电弧炉×1 | 真空冷冻机×1 | 3台 |
| 铂处理产线（子线合并） | 大化学反应机×N | 蒸馏塔×N | 离心机组×N | 多台 |

**实施时确认**：
- 每台多方块机器主机的准确物品注册名和 meta 值（从 GTNH `ItemList` 枚举或 `gregtech:gt.blockmachines` 元数据确认）
- 激活时消耗机器物品的数量（每步 1 个控制器方块，多步则数量累加）
- 现有 `ProductionLineControllerGUI.activateRecipe()` 用 `getUnlocalizedName` 匹配机器，实施时需改为按 item+meta 精确匹配

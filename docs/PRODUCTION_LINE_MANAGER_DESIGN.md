# 产线管理器（Production Line Manager）设计文档

> 版本锚点：设计稿 v6 · 目标发版 4.1.0（第 1 期）+ 4.2.0（第 2 期）；v6 依据 2026-10-16 评审，A1–A7 与 O1–O8 已拍板
> 作者视角：以用户的四点原始需求为纲——**①自动检测 FTB/ServerUtilities 团队区块加载的所有机器的工作情况 ②知道每步输出的产物是什么 ③没工作的记录上次产物 ④在产的排最上面**；辅以流程图化 UI（参照 GTNH huijiwiki RecipeCalculator"配方一览"）。
> 工作目录约定：本模组 = AE2-QoL（GTNH 2.9.0-beta-3，MUI2 编译 2.3.88 / 实例运行 2.3.91，ServerUtilities 2.4.9）。

## 一、目标与非目标

### 目标（v1 全覆盖）
1. 玩家可自建**产线组**（自定义名称），把**团队已加载区块内的 GT 多方块机器**按"步骤"组织进去；
2. **产线定义可编辑**：步骤可新建/修改/删除/排序；步骤的名称、机器类型、输入/输出清单（含每周期量）都可以改；
3. **导入双通道**：
   - **A. Wiki JSON 粘贴**：直接粘贴 huijiwiki RecipeCalculator 模板页的结构化 JSON（如"稀土处理/独居石主线"现成页面），一条产线秒成型（含分支/层级/理论配比）；
   - **B. NEI 逐步导入**：在 NEI 配方界面点本模组按钮，捕获该配方"输入/输出 + 数量"追加为一步，自动匹配链扣连线；
4. **流程图页**：wiki"配方一览"的游戏化形态——分支选择 chip + hierarchy 分段 + 步骤行（在产/空闲/瓶颈徽标 + AE 存量 + 理论配比）；
5. **机器绑定**：按"步骤的机器类型名"过滤的候选清单（团队已加载机器）勾选 + 手持绑定卡 Shift+右键机器兜底；**一台机器同时只属于一个产线**；
6. **步骤小 UI**：点步骤框弹出：软暂停/开启、行内【高亮】【传送】、补绑机器、删除步骤；
7. **总输入/总输出汇总面板**：整线外购物料与最终产出**分物品**列出，双口径——**累计**（BigInteger，跨重启持久）与**平均**（自创建线性平均）。

### 非目标（明确不做 / 留待后续）
- **物理停机**（覆盖板发红石真停机）——用户已定 v1 软暂停；留 v2；
- **滑窗平均**（近 1h/10 分钟）——留 v2（v1 只有自创建线性平均）;
- **浮点连线图**（真正的节点连线绘制）——v1 用"分支 chip + 层级分段 + 步骤卡"的 wiki 卡片式布局替代；
- **单方块机器**进入产线——v1 只收 `MTEMultiBlockBase`；留肯后扩展；
- **机器粒度的暂停**——v1 粒度=步骤，机器级留后。
- NEI 支持任何 handler——v1 覆盖 GT 机类配方 handler（PositionedStack 列表形态）；其余 handler 遇到则提示"暂不支持该类型"。

## 二、名词与数据模型

### 2.1 核心对象

```
ProductionLine（产线）
├─ id: UUID                       // 有界生成，日志可追踪
├─ name: String                   // 用户可改（如"XXX 产线"）
├─ ownerTeamId: TeamUUID          // ServerUtilities ForgeTeam 的 ID（创建者所属团队）
├─ networkId: UUID                // 锁定的 AE 网络：创建时取创建者终端绑定网络的 id（O2 拍板；采样/展示只认它）
├─ createdAtMs: long
├─ steps: List<ProductionStep>
├─ linePaused: boolean            // 软暂停（整线）
└─ pausedStepIds: Set<String>     // 软暂停（步骤级，存 stepId——A1 拍板：一切步骤引用一律用稳定 id，不用下标）

ProductionStep（步骤）
├─ id: String                     // 稳定唯一 id（UUID 短格式；增删/排序不改 id——A1 拍板：绑定卡/暂停位/链扣全部引用 id）
├─ name: String                   // 如"硫酸独居石粉稀释"
├─ machineType: String            // 机器稳定键：GT MTE 内部注册名/类型标识（本地化名仅展示与输入提示——A2 拍板；服务端语言表不可靠）
├─ inputs: List<ItemRow>          // 输入[{物品Key, 每周期量}]
├─ outputs: List<ItemRow>         // 输出[{物品Key, 每周期量}]
├─ machines: List<MachineRef>     // 绑定的实体机器 [(dim,x,y,z),…]
└─ softPaused: boolean

ItemRow（物品条目）
├─ key: String                    // "itemName@meta" 或 fluid 名（统一串格式；v1 忽略 NBT——有意取舍，见 §八风险 5）
├─ amount / cycle: long           // 每周期数量
└─ isFluid: boolean

MachineRef
├─ dim, x, y, z
└─ lastSeenEpochMs                // 最近一次扫描到它存活的时间（离线展示）
```

### 2.2 与 wiki RecipeCalculator 模板的同构映射

| wiki JSON 字段 | 本模组数据 |
|---|---|
| `recipeQuery[i].name` | `steps[i].name` |
| `recipeQuery[i].type` | `steps[i].machineType`（经"机器类型解析器"归一为稳定键；解析失败逐项标红列出——A2） |
| `recipeQuery[i].input`（逗号分隔） | `steps[i].inputs`（每项按 1 起，Lua 名→物品键） |
| `recipeQuery[i].output` | `steps[i].outputs` |
| `recipeQuery[i].branch` / `branches` | 分支标签（步骤级 chip） |
| `recipeQuery[i].hierarchy` | 层级分段标题（渲染为分段） |
| `groups[]` | 分支组（chip 选择器数据源） |
| `start[]`（name+amount） | 起点（外部输入）清单 |
| `env[]` | 循环介质名单（不计入水位Warning） |

**导入映射规则**（Wiki JSON → 游戏内产线）：
1. 名称转 key：需要**名称→实际物品/流体注册键**的解析函数。找不到的条目标红提示"未注册：xxx"（不静默丢弃——不丢内容铁则）；
2. 分支组生成 chips：默认选第一个分支作为"激活路线"，其余照常收录（用户可切）；
3. `start` 物品进入"总输入"清单；`env` 物品进入"循环物"名单（告警豁免）。

### 2.3 持久化

- **存档**：`<world>/data/AE2QoLProductionLines.dat`（WorldSavedData，同步加载），结构=所有产线的序列化（NBT 复合列表）；**文件首部带 `schemaVersion: int`**（v6 补，B2——后续格式升级以此为迁移依据；本项目已有 MTE ID 迁移的前车之鉴）。
- **速率采样**（内存，不落盘）：每条产线维护
  `Map<StringKey, Deque<Sample>>`——每个**外部输入/最终输出物品**每 10 秒一个样本 `(epochMs, aeStock long)`；
  速率 = （首尾 stock 差） ÷（时间差）；窗口长度自适应（最少 3 个样本，最长 30 分钟，环形上限 180 点）。
  注（B7）：环形缓冲不持久、重启即丢——4.2.0 的瓶颈检测若需要跨重启历史，须先拍板历史样本持久化。
- **累计计数**：每个物品 `cumulative BigInteger`——每次采样比对 Δ 存量（>0 计入输出侧，<0 计入输入侧），**跨重启持久**（SavedData 内）；存量读数本身是 long，BigInteger 只用于累计与平均。
- **平均/小时** = `cumulative ÷ max(1h, now − line.createdAtMs)`（与 §6.2 统一口径，含 1 小时护栏；BigInteger 除法）。
- 写盘节流：累计以 NBT 增量缓存、60s 同步一次（§八），服务器崩溃最多丢 60s 累计——明示取舍。

### 2.4 AE 数值的来源（v6 重写——A3 拍板）
- **网络归属**：产线创建时，以**创建者打开产线页的那个终端**所绑定的 AE 网络锁死为 `line.networkId`；此后采样/展示只认这个网络，UI 在产线名旁注明口径（同团队两个基地两个网络看同一线不混计）。
- **物品存量**：服务端按 `line.networkId` 取 IStorageGrid，**每轮采样做一次全表快照（getStorageList）再逐键匹配**——不做逐物品查询。读数基础复用现有 `AeStockReader`（item 走 findPrecise；fluid 必须走 fluidID 遍历匹配——AEFluidStack.equals 的引用相等坑已在案）；返回 long，BigInteger 只用于累计/平均。**采样路径不得继承 AeStockReader 的静默 catch**：失败必须 `warnOnce` 记日志（坑 #6）。
  - 勘误：初稿写的 `RequestProvidersListPacket` 是样板上传的"配方提供者枚举"包，与存量查询无关（见 RequestProvidersListPacket.java:180-238），已弃用该引用。
- **运行状态**：绑定机器的 `mMaxProgresstime > 0`（20 tick 分片扫描，每 tick ≤32 台，只读）。
- **离线/在线**：机器所在区块有 TE 实体 → 在线；无 → 离线（保留行、"离线"徽标）；连续 ≥3 天未询到 → 行标"失效"，可解绑（O5）。

## 三、用户旅程

```
获取产线定义
  ├─ A. wiki 复制 JSON → 游戏内"粘贴导入" → 自动解析/建组
  └─ B. NEI 逐步导入 → 步骤追加
       └─ 手动补充（新建空步骤、改字段、排序）
        ↓
绑定机器（每步）
  ├─ 按机器类型自动推荐候选 → 勾选
  └─ 绑定卡 Shift+右键机器（兜底/精细控制）
        ↓
日常监测（库存统计终端 · 新增「产线」页签）
  ├─ 流程图页：分支 chip + hierarchy 分段 + 步骤行
  │    行内：机器类型/绑定台数(在产/总数) / 主产物 / AE 存量 / (v2: 实测速率/利用率/瓶颈徽标)
  ├─ 汇总面板：总输入 / 总输出（累计 + 平均）
  └─ 步骤小 UI：软暂停 | 高亮 | 传送 | 补绑 | 删步骤
```

## 四、UI 规格

### 4.1 入口位置
库存统计终端（ID 32107）新增左页签**「产线」**（第三页）。页内两级视图：**产线列表**（左）/ **产线详情**（右，选中产线的流程图）。

**列表行**（v6 补，O4/B3）：产线名 · 步骤数 · 在产台数汇总 · 归属团队名；行尾操作【重命名】【删除】——删除整条产线 = 双击确认 + 聊天二次确认，不做回收站。

### 4.2 流程图页（详情）

```
┌──────────────────────────────────────────────────────┐
│ 蓝合金产线 · 配方一览        wiki 导入 · 分支: 不添加富铈▼ │
├──────────────────────────────────────────────────────┤
│ [branch chips 区（多分支时显示，单分支隐藏）]                  │
│ ▼（级别分段标题：主线 / 铪锆分支 / 二氧化铈分支 / 其它分支）       │

│ │ 步骤1 · 粉碎的独居石矿石煮解   大型煮解池            │ │
│ │ 绑定 3 台 · 3 在产 · AE 存量 58k     [小UI]          │ │

└──────────────────────────────────────────────────────┘
```

**步骤行的字段**（v1）：
1. 步骤名（截断显示，悬停 tooltip 全量）；
2. 机器类型（第二行小字）；
3. 绑定台数 `n 在产 / m 总`（mMaxProgresstime 读数）；
4. 主产物（agents 排序的第一条输出）数量（每周期 + AE 存量引用）；
5. [小UI] 按钮。
6. 顶部状态徽标由 running 数决定（全部在跑=绿"在产"；部分=黄"部分在产"；0=灰"空闲"；人工软暂停=紫"已暂停"）；
7. **失效绑定**（v6 补，O5）：绑定机器连续 ≥3 天未询到 → 该绑定标"失效"，行内可一键解绑。

**branch chips**：多分支的产线顶部横排 chip（单选）：选择后**只显示被选中分支链路上的步骤**（branch 标签过滤），未选中的步骤灰化（还可见，供参考）。

**hierarchy 分段**：`hierarchy` 数组相同的步骤聚在同一分段标题下（例如▼铪锆分支），顺序按原 JSON 出现次序。

### 4.3 步骤小 UI（点击步骤行的 [小UI] 弹出子面板）
- **暂停/开启**（软，写产线定义，**不动 GT 机器本体**——铁则明示"不触发机器写操作"）；
- **高亮 / 传送**（复用 WirelessHighlightPacket + Teleporter 设施；授权=目标机器在**同一团队**的已加载区块内）；
- **补绑机器**（进入绑定模式：终端里选该步 → 手持绑定卡 Shift+右键机器 → 绑定卡 NBT 带目标 step 引用与产线 id）；
- **解绑机器**（v6 补，O5：弹出该步骤已绑定机器列表逐条解除；流程图上"失效"行给一键解绑）；
- **删除步骤**（双击确认——防误触）；
- **编辑步骤**（跳转到 4.4 编辑子面板）。

### 4.4 步骤编辑器（子面板）
- 字段：名称（TextFieldWidget 单行）、机器类型（单行文本）、输入行列表 / 输出行列表（每行 = 物品 key 文本框 + 每周期数量框 + [删]）；[+ 添加输入行] / [+ 添加输出行]；
- [保存]（写产线定义 + 广播流程图刷新）/ [取消]；
- 行内的物品 key 输入支持"从 AE 里搜索挑"（走库存数据已知的物品名列表）——输入更顺手；
- **新建空步骤**入口在流程图页顶部（[+ 新建步骤]），打开同一编辑器，字段全空。

### 4.5 NEI 逐步导入流程（v6 重写——A6 拍板：导入必须有"目标上下文"）
- **前置**：导入目标是玩家在终端里**先选中**的产线与插入位置；该选择以**按玩家会话**状态保存（退出终端/登出即失效），NEI 捕获后服务端追加到该会话目标上——绝不做"全局上一个导入步骤"（两条产线被两名成员同时导入必然串线）。未选目标时点 NEI 按钮 → 聊天提示"先在库存统计终端·产线页选中目标产线"；
- NEI 配方界面出现本模组按钮（复用智能通配样板的 NEI 注入路径：`SmartWildcardNeiDragHandler` 同款事件体系）；
- 点击按钮 → 客户端捕获当前展示配方的 PositionedStack 列表 → "输入[] 输出[] 数量都走 stackSize"（含流体）→ 发包给服务端；
- 服务端追加为一步（name = handler 展示名 + 序号；type = 经机器类型解析器归一的稳定键），然后**自动连线**：取会话目标产线"最近一次导入步骤"的 outputs 与新步骤 inputs 的**第一个交集**，命中 ⇒ 排在其后并写链扣标记（标记存 stepId 对）；未命中 ⇒ 末尾标"未连接"。自动连线允许后续手动改（编辑器可调顺序/删链扣假设）；
- 分支支持：v1 不在 NEI 导入中创建 branch，默认无标签（hierarchy 无）；用户可后续在**编辑器**里手工补 branch/hierarchy 字段（编辑器一行字段）。

### 4.6 Wiki JSON 粘贴导入流程（v6 重写——A5 拍板：补齐解析宿主与传输路径）
- 终端「产线」页顶部 [+ 新建产线] → 弹出面板有两个 tab：【粘贴 wiki JSON】/【从 NEI 逐步导入】；
- 【粘贴 wiki JSON】：**单行长文本框**（实测 MUI2 2.3.88 全树无 TextArea/multiline 组件——参考树 ModularUI2-2.3.88 grep 零命中；huijiwiki 导出的 JSON 常为单行压缩体，原生 TextFieldWidget 支持 Ctrl+V 粘贴长串）。超长/多行内容走**多段粘贴**：文本框逐段粘贴 [追加] 参数（客户端内存顺序拼接），页脚实时显示已积累字符数；
- **传输路径**：客户端预收集完成 → **分块上传包**（每块 ≤24KB，带 (importId, seq) 重排，服务端拼装校验总长度）→ 服务端权威解析与建线；总上限 1MB，超限拒绝并提示"拆分产线或改用文件方式"（约束写明，不静默截断）；
- 解析严格性：不完整/重复 id/partFailed 段→ 逐项**列错误报告**（哪一步、哪个字段失败、值是什么），全部通过才建立产线；部分失败可用"跳过无法解析的步骤，仍建线"复选框（默认关闭——不静默）；
- 分支/层级全部照 wiki 字段收录；名称→注册键与类型→稳定键的解析失败清单复用同一报告格式。

## 五、机器绑定细节

### 5.1 候选清单生成（v6 重写——A2/B5：稳定键匹配 + 扫描预算）
- 输入 = `step.machineType`（**稳定键**：GT MTE 内部注册名/类型标识；输入框带已存在类型的模糊提示，本地化名仅用于展示行）；
- 匹配 = 机器的稳定键与 machineType 一致或按注册名前缀包含（大小写不敏感）——**不用本地化名做服务端匹配**（1.7.10 专用服语言表与客户端不一致，坑式缺陷）；
- 扫描域 = **该产线所属团队 + 已加载区块**内的全部 `MTEMultiBlockBase`（ServerUtilities `ClaimedChunks.instance.getAllChunks()` 过滤 `team==`, `isLoaded()`）→ 逐 chunk 的 TE map 中收集；
- **扫描预算**（v6 补，B5）：仅玩家打开"绑定面板"时算一次（缓存 5s）；单次扫描 ≤50ms，超预算即截断并提示"候选过多已截断，请缩小匹配类型后重试"（不静默吞）；
- 勾选即可绑定；同一机器**只允许属一条产线**（校验：机器坐标在其它产线的机器列表出现 → 拒绝并提示在哪个产线里）；
- 同一步可绑多台（并行聚合）；同组不同步重复绑同一台 → 拒绝。

### 5.2 绑定卡（兜底入口）
- 物品名："产线绑定卡"；
- NBT 字段：`lineId, stepId`（v6 改——A1：不再用 stepIdx；由终端选中的步骤写入，或"绑定模式"下默认"当前选中步骤"）；
- 交互：手持卡 + **Shift + 右键**机器（多方块控制器/任一样式块） → 服务端校验：
  1. 卡上产线存在 & 属于该玩家团队；
  2. 机器是 `MTEMultiBlockBase`；
  3. 机器坐标在该团队已加载区块（或同团队范围）；
  4. 无其它产线持有它；
  → 绑定成功（聊天提示 + 卡 NBT 保留最近绑定列表方便撤回）。

## 六、数据采样与汇总面板

### 6.1 采样（后台服务）
- 触发节奏：**每 10 秒**（服务端主循环切片预算内），**只对已绑定机器的产线**做采样；
- 每次采样动作：
  1. 对产线内所有**非 env、非分支屏蔽**物品查 AE 网络当前存量（每轮做一次全表快照再按键匹配——v6 A3 拍板；不做逐物品查询）；
  2. 与上一个样本比较，`Δ>0 → 累计输出 += Δ`，`Δ<0 → 累计输入 += |Δ|`（逐物品）；
  3. 机器运行状态读数（分片：每 tick 最多 32 台，剩余下 tick）。
- **Throttle**：全服并发活跃产线上限=同时采样的产线上限 16 条，超出排队（FIFO）；单产线采样自身耗时护栏="单次 ≤ 3ms"（超时丢弃本次，下轮再试）；**连续 3 次超时/失败 → 该产线暂停采样 5 分钟并 `warnOnce` 去重记日志**（v6 补，B6——不静默吞，恢复时再打一条）。
- **严禁**：采样过程调用 `setActive`/写机器（只读写抽样/记录数据），不写 GT 字段。

### 6.2 汇总面板口径
- **总输入** = 产线所有步骤 inputs 中，**"当前产线主链上无上游步骤提供"的物品**（即非链扣项）∪ `start[]` ∪ 各步骤**额外外部输入**；同物品跨步骤合并。
- **总输出** = **无下游步骤消耗**的物品（末端产物）；同物品跨步骤合并；
- **Branch 路线敏感**：被选中的 branch/hierarchy 主链参与汇总；被屏蔽分支不算（用户切换 branch → 汇总重算）。
- 展示：物品名 + **累计**（BigInteger 简写格式，复用 `formatKMG(BigInteger)`）+ **平均/小时**（=累计 ÷ 运行小时，运行定义`max(1h, now − createdAt)`）。

## 七、软暂停语义（明确）

- `softPaused`（步骤级/整线级）**只是产线定义内的状态位**：
  - 步骤行徽标显示"已暂停"（紫）；
  - 该步骤的**期望运行假设**在后续 4.2.0 的"瓶颈检测"里被豁免（不参与报警）；
  - **完全不触碰** GT 机器（不改 isAllowedToWork、不动红石、不覆盖盖板）；
- 玩家若想真停机：自己手动关机器（或等 v2 的覆盖板方案）。

### 权限与安全
- 产线归属 = **创建者所属 ServerUtilities 团队**；查看/编辑/绑定/暂停 = 团队成员（`EnumTeamStatus` 判定）；
- **高亮/传送授权**：目标机器必须在**当前请求者同一团队**的已加载/已声索区块里（就算在产线表里，如果机器所在区块已转他人，也要拒）；
- **团队生命周期**（v6 补，B4/O6 拍板）：创建者无团队 → 禁止新建产线（页面提示去 ServerUtilities 建队）；产线归属团队**解散** → 产线转**只读孤儿态**（成员不可见他、OP 可见可删，接管命令留后续）；
- **v6 勘误**：库存统计终端现有传送/高亮**没有任何区块团队校验**（`StockMonitorActionPacket` 现状零 team/claim 引用）——"target chunk team 校验"是产线功能**新增**的行为，不是对齐既有；
- 网络包一律 `ServerTerminalHelper.scheduleServerTask` 归队 + builder 权限校验（对齐 P1-011/P1-2 先例）；
- 数值接口（AE 存量）同样要求 player 在该网络的终端会话内（isActiveViewer 口径，防随意拉数据）。

## 八、性能预算（红线）

| 项 | 预算 |
|---|---|
| 采样频率 | 10s/次，且只采样"被打开过界面的活跃产线"（最多 16 条，其余挂起） |
| 单次采样耗时 | ≤3ms（超时弃本轮）； BigInteger 计算量在千物品级为毫秒级，可控 |
| 机器状态读数 | 每 tick ≤32 台分片；*读* `mMaxProgresstime` 是字段读，无搜索 |
| 机器候选清单生成 | 仅当玩家打开"绑定面板"时算一次（非后台循环）；缓存 5s；**单次 ≤50ms 超预算截断并明示**（v6 B5） |
| UI 快照广播 | 行数据 StringSync/结构化包（照 fix6 范式），有变化才广播（脏标记） |
| 持久化写盘 | 编辑保存 + serverStopping 才写盘；采样和状态不落盘（除累计，每次采样以 NBT add 形式缓存，节流 60s 同步一次） |

### 已知风险与宽解
1. **物品名称歧义**（wiki 中文名 → 物品键）：未命中 → 行标红"未注册"+ 玩家可编辑更正（不静默删）；
2. **分支复杂产线**（如"两条 alternative + 多 hierarchy"）：v1 UI 已包含 chips + 分段；连线视觉省略；
3. **ServerUtilities 依赖**（O1 拍板）：走 **compileOnly 本地 jar（锁版本，放 libs/）+ `Loader.isModLoaded(真实 modid)`（modid 以对方包内 mcmod.info 为准，实施时核实——坑 #18）+ 关键类可解析双判据**（`Class.forName`，坑 #18/#19 现成范式 `PhIntegration`）；未装/守卫不过 → **整个产线功能禁用 + 页面提示，不抛出**，且三条守卫分支各打一行日志（已启用 INFO / 未检测到 INFO / 注册失败 ERROR——坑 #19）；v6 时点：依赖 jar 尚未入 libs/，是实施第一步；
4. **数据一致性**：同一玩家远程开多个同网络终端 → 行快照以服务端权威，多端一致；
5. **NBT 变体物品**（v6 补，B1）：v1 物品键忽略 NBT（item@meta 级聚合），NBT 变体会被合并——有意取舍，后续版本再扩键位；
6. **累计口径不回溯**（v6 补，A4）：汇总分类随 branch 切换/步骤编辑即时重算，但累计计数器独立累计、不重置——口径变更对历史数据有污染，UI 明示"口径变更于 X"（已知取舍，诚实呈现）。

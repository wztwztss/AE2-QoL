# 3.35.0-fix8 → 3.35.0-fix9 更新日志

## 🔴 修复：库存检测覆盖板标记的流体在模组更新后"随机变换"（用户实测恶劣 bug）

**现象**：每次添加/移除/更新模组后，覆盖板里已标记的流体变成别的流体。

**根因**：GT 的流体显示物品（`ItemFluidDisplay`，NEI 里所有流体的占位形式）用 **meta（数字 ID）** 表示流体，而这个 ID 是启动时按模组加载顺序**动态分配**的（`GTUtility.getFluidDisplayStack` 字节码 offset 13-22 实证：meta = `Fluid.getID()`）。本模组两处读取路径（覆盖板幻影槽识别、NEI tooltip）都按这个不稳定 ID 解读流体——模组列表一变，ID 表整体漂移，同一样品就解出另一个流体。

**修复**：两处读取改为**稳定键优先**——优先读物品 NBT 里 GT 自己写入的 `mFluidMaterialName`（流体材料名字符串，跨版本/跨模组列表稳定），名称解析只做精确匹配（模糊 contains 在注册表无序遍历下正是"随机错流体"的第二个来源）；无 NBT 的老数据才回退 meta 读取。

**对已错数据的影响**：存档里的 Phantom 自带稳定键，修复版能按名字解出正确的原流体——**动过其它 mod 也没关系**。个别极早期无该键的物品只能重放一次；修复后新标记全部带稳定键，不再恶化。

**涉及文件**：`cover/stockmonitor/StockMonitorCoverData.java`（覆盖板识别）、`client/NetworkInventoryCache.java`（NEI tooltip）。

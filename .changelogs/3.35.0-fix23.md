# 3.35.0-fix22 → 3.35.0-fix23 更新日志

## 🔴 修复：电网监控页统计超 9.2E 被"截断"（用户实测回归）

**现象**：电网余额超过 9.22E 后，监控页的"变化 1小时/10分钟"恒为 ↑ 0.00、"预计耗空时间"恒为 ∞、瞬时速率与统计总量停在 9.22E 封顶值。

**根因（三层叠加）**：
1. fix11 的统计总量/窗口和采用**饱和口径**——越过 `Long.MAX_VALUE` 后永远封顶在 9.22E；
2. 统计数据源是 `getGridEULong`（钳制版长值快照）——两个历史快照相减恒 0；
3. 速率/预测行内部还有 long 除法与阈值的设计。

**修复（统计全链路 BigInteger 精确化）**：
1. `GridEnergyStats` 核心（总量/100-tick 窗口和/lastEU/1h-10m 历史快照）改 **BigInteger** 精确累加；`tick(BigInteger)`；
2. 数据源换成 `getGridEUBigInteger(owner)`（与"电网总能量"行同一精确来源）；钳制链从统计域退役（刻意 long 域的补电算术/仓 WAILA/wGE 兜底原样保留）；
3. 7 个统计同步值（总输入/总输出/瞬时×2/变化×2/平均输出）改 `StringSyncValue` 承载**十进制串**，客户端按**显示模式**（常规/科学/KMG）格式化——模式切换按钮继续有效；安培档名对超 long 量级封顶；
4. **预计耗空时间**：分子/分母 BigInteger 除法，">100年"阈值 BigInteger 比较——不再恒 ∞。

**存档兼容**：统计写入新十进制键（`gridTotalInX/OutX`、`gridEU10mX/1hX`），同时保留旧 long 键（旧版本模组读本存档不崩）；读档优先新键，缺失回退旧键。

**涉及文件**：`hatch/adaptive/GridEnergyStats.java`、`AdaptiveNetwork.java`、`AdaptiveNetTerminal.java`。

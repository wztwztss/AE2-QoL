- 服务端：频道名限 64 字符（超长截断并提示）、总数封顶 256（拒建第 257 个并提示）——旧实现单条最长 32KB 且无总量限制，全部写进世界存档。

### 3.35.0-fix14 — 库存统计终端 viewer 会话注销（P2-5）

### 3.35.0-fix16 — 畸形动作包 NPE 拦截 + 零注入死 Mixin 摘除 + 配置漂移补齐（P2-14 + P2-16）

- `MixinBaseMetaTileEntityWaila`：零 `@Inject` 却登记在**双端段**（专用服也被转换，类里引用 `Minecraft` 存在类加载风险）。从配置摘除（行为零变化），文件保留作未来实施参考。
- **附带发现**：仓库根 `mixins.ae2_qof.json` 缺 `MixinSteamEntityCrusherTuning`（3.32.0-fix5 只改了 jar 内那份）——两份配置已补齐并 `cmp` 逐字节校验一致；台账计数改准 43 = mixins 27 + client 16（此前记 43 实为 44）。

### 3.35.0-fix19 — 无限元件内容/统计回传补归属校验（P2-13）
- Stats/View 两个 C2S 包旧实现只凭 storageId 就回数据——元件 UUID 虽是 122 位随机数，但一旦泄漏即无门槛拉走**完整内容分页**。新增 `InfinityCellAccessPolicy`：请求玩家**背包 ∪ 当前打开容器**必须真实持有该元件（与 NEI U 键/tooltip 的合法触发面精确对应，不破坏驱动器/箱内悬停）；拒绝时回 null 分页（与"存档不存在"同语义）+ 每玩家 60 秒限频 WARN。

## 性能与内存（fix15、fix17、fix18）

### 3.35.0-fix15 — 无限元件 NbtKey 驻留 + 原型缓存收缩（P2-7 + P2-8）
- `NbtKey.of` 旧实现每次物品操作付**两次全树遍历**（深拷贝 + 建规范串）。canonical 串是内容纯函数 ⇒ 单次遍历建串，命中驻留缓存即跳过深拷贝；canonical 规则一字未改（**存档身份不变**），等价性经 10 类 NBT 对照实验**逐字节实证**。
- 物件原型缓存按账本收缩（只在"缓存明显大于账本"时触发，正常枚举零额外开销）。
- `FluidStackKey`/`EssentiaStackKey` 同链路自动受益。

### 3.35.0-fix17 — 仓识别反射负缓存 + getter 缓存（P2-11）
- `AdaptiveHostIndex` 三个反射点在每 20 tick 热路径上反复重付代价：无 `maxAmperes` 字段的类（普通 GT 能源/动力仓——白名单允许）每次抛 `NoSuchFieldException` 不缓存；`getAmperes` 完全无缓存。补三组负缓存 + getter 缓存；**负缓存只记查找失败**（调用期瞬时失败仍可重试，不固化成永久禁用）。

### 3.35.0-fix18 — 兼容仓安培写入扫描节流（P2-12）
- 每 20 tick 无条件全量扫描（即使网络没有 TecTech 兼容仓）→ 两级修复：① 空网络短路（可证明行为等价）；② 兼容仓**发现**按 (owner, frequency) 缓存 5 秒 TTL，**安培写入仍每秒**（写入语义不变）。全量扫描 ×1/5；新激光仓 ≤5 秒被发现（安培本就要周期重写，延迟无感）。

## 数据管理（fix21）

### 3.35.0-fix21 — 元件数据文件管理命令组（P2-10）
- 拆掉的元件数据文件永久保留 → 新增 `/ae2qof cell`（**OP 等级 2**）：
  - `list [页]`：全部数据文件清单（大小/最后修改时间，倒序）；
  - `info <uuid>`：四通道（物品/流体/源质/EU）类型数 + 数量摘要；
  - `archive <uuid>`：**移动**到 `data/AEInfinityCell/archive/`（不删除；脏数据拒绝；同名拒绝）；
  - `restore <uuid>`：移回（现网同名拒绝覆盖）。
- 设计取舍：自动判定"孤儿"需世界级物品扫描且元件可能在未加载区块（误删不可逆），判定交给管理员 + 移动可恢复。归档后元件物品若重新出现读成空元件（内容可 restore），聊天内有明示。

## 收口（fix20、fix22）

### 3.35.0-fix20 — 通配样板编辑器会话化（P2-15）
- 9 个 static 可变状态 → build 内**每次打开一份**的会话局部变量（lambda 捕获，旧名代码引用零残留）：双端构建互覆盖、跨会话互踩、单机"编辑中途被重置"类隐患全消。

- 行为差异（有意）：重开编辑器回到第 1 页。

### 3.35.0-fix22 — 空 catch 批量收口（P2-17）
- 复盘实测 **204 处**空 catch（比审计快照的 183 多），绝大多数是刻意的 Throwable 防御边界。存储写路径高风险子集仅 **3 处**：
  - `CoverRegistry` legacy 迁移合并整块静默吞（老存档升级丢数据不可见）→ 补 WARN 保留异常；
  - 智能倍增开关 / 统计终端翻页两处 `markDirty` 失败 → 补 WARN（周期保存兜底）。
- 其余约 201 处登记口径不修改（处理准则已写入审查报告"批处理记录"）。
